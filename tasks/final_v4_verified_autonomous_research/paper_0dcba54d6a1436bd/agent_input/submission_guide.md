# Submission and evidence

Write `report/results.json` under the supplied JSON Schema and `report/report.md` as a readable scientific report. Use your own model names, methods, study branches and evidence design. No hypothesis count, fixed result panels, calculation count or particular software is prescribed. A research log is a concise record of useful decisions, observations and responses, not private internal reasoning. An empty model array is permitted where no explicit model was formulated; this does not establish a successful investigation.

Identify the actual molecular systems, electronic states and environments used. Give unique IDs for systems, methods, records, results and claims. All references must resolve to those IDs. Each record identifies a real calculation or analysis and links workspace-relative `outputs/`, `data/` or `code/` artifacts with SHA256, their role and a precise section/line/table locator. Preserve native outputs, inputs and any analysis needed to reproduce derived numbers. A path or hash is not itself scientific evidence. Use tool job identifiers when available. Separate generated evidence from supplied facts or citations; never present a supplied value as a new calculation.

Every reported numerical quantity requires a unit, definition, object mapping and uncertainty statement; dimensionless quantities explicitly say so. Method-specific evidence belongs in additional named fields or linked artifacts. Report identities and stoichiometry for transformations, conventions for differences, and evidence appropriate to any claimed geometry, state or response. Failed, constrained and unvalidated structures must not be relabeled validated minima. A claim of a minimum requires stationarity and curvature evidence or a justified equivalent; a transition-state claim additionally needs relevant saddle/connectivity evidence. These are conditional validity requirements, not prescribed investigations.

Support/refutation claims link results; results link records; records link actual artifacts. State why the evidence discriminates the claimed explanation and what uncertainty or unexamined scope remains. A contrary, bounded negative or unresolved conclusion is reportable; it earns a scientific item only when actual evidence establishes the particular proposition assessed by that item. It does not automatically satisfy a different reference finding. Missing work cannot be converted into evidence of absence or non-identifiability. Agreement with supplied observations, fluent prose, raw job counts and filling every field do not establish success.

Use `complete` only for a substantively answered bounded question, including a demonstrated negative or unresolved answer. Its minimum format requires at least one completed calculation or analysis record, at least one numerical quantity in a record or result. This minimum does not establish adequate coverage or scientific success. `partial` and `bounded_failure` allow honest incomplete work and diagnostic evidence; list missing work. Schema acceptance validates format, not scientific completion. No calculation is required just to fill a failure record if the environment prevented it: report that limitation honestly. Untested assertions earn no result credit.

State whether each prediction or decision is prospective, retrospective or unsupported by an independent trace. Self-written dates do not establish ordering. All supplied data are visible; there is no blind held-out interface. Use only the tools and resource limits actually exposed by the runner; do not assume a software license, fixed CPU allowance or extra experimental access.

## Scientific scoring

Scientific scoring uses a single 100-point total consisting of independent final scientific conclusions. Each item earns its fixed points when supported by valid evidence, or zero otherwise. Research effort, software use, report completeness and protocol execution earn no separate points. A negative, contrary or unresolved conclusion may be reported honestly; it earns an item only when the evidence establishes that item’s specific scientific proposition. Neither an outcome label nor a generic uncertainty statement earns credit.

## Final-results contract

Only the final scientific questions in task.md receive points (paper_science_v3 / final_results_100). Computed structures, frequencies, state assignments and native files provide evidence for their associated claims, with no independent process score. `research_log` entries document useful decisions but are not a scientific scoring gate; an empty log is allowed. Supplied facts must be distinguished from newly computed results.
