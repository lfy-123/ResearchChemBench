# Submission guide

Submit `report/results.json`, `report/report.md` and actual inputs, outputs, logs and analysis code under `research/`, following `submission_schema.json`.

Use stable IDs for hypotheses, investigations, evidence and conclusions. Every evidence/investigation link and conclusion/evidence link must resolve. List each referenced native artifact in `reproducibility.artifact_index` with a safe relative path. Preserve molecular identity, site mapping, state, units, conditions and quantity definitions. Use null with an explanation when a quantity is unavailable.

Research status (`complete`, `partial`, `execution_failed`) and question status (`resolved`, `partially_resolved`, `unresolved`) describe different facts; neither label establishes a scientific result. Record actual methods and outcomes without private chain of thought. No fixed hypothesis, conformer, tool or job count is required. Failed calculations must be identified with their real logs.

Scientific credit is assigned only to supported final conclusions. Execution, artifact completeness, resource use and honest failure reports are not independent score items. Evidence and appropriate validation are prerequisites for each claim. An established physically equivalent explanation or a supported finding of equivalent para sites may answer the question. Actual structural and numerical site evidence remains necessary; distinguish local results from any justified ensemble average. Generic limitations, unsupported speculation or an unresolved status alone earn no conclusion credit. Schema validation does not certify scientific correctness.
