# Agent 操作指南：从双轴评分迁移到论文科学结果 V2

版本：2026-10-17。适用对象：ResearchChemBench 任务维护 Agent；本文件不是被评估 Agent 的公开输入。

## 1. 目标与不可改变的边界

把过程分 P 与科学分 S 的双轴评价，转换为只评价科学结果的 100 分清单。每篇同时包含中间科学发现与最终科学结论。最终分数为各独立评分项之和，不再计算过程分、过程乘数、工具效率或研究投入奖励。

科学结果不限于数值。分子连接关系、结合拓扑、电子/自旋分布、构象可达性、竞争通道排序、环境效应以及由这些结果支持的最终解释，都可以独立评分。对解释型问题，应优先保证定性科学发现与综合解释的权重；不要把论文中能找到的每个数字机械地设为评分项。

除非用户另有明确授权，以下内容必须逐字节保持不变：

- agent_input/ 中的任务指令、结构、实验观察、资源说明、JSON schema 和提交指南。
- task_info.json 的任务身份、科学范围与交付要求，以及 paper_route.md。
- 历史运行结果、历史评分、正在运行任务的冻结快照和论文原件。

不要把私有论文答案、验证路线或评分清单放进公开输入。不要要求被评估 Agent 复刻验证者的搜索路径、工具序列、假设数量或软件选择。等价且有证据支持的计算方式应按物理结果可比性评价。

## 2. 区分四种资料

| 资料 | 用途 | 禁止混淆 |
|---|---|---|
| 公开任务与输入 | 确定科学问题、已知条件、范围和交付内容 | 不因论文有更多结果就扩大任务范围 |
| 论文正文与 SI | 确定目标、物理定义和受支持的结论 | 作者数字不是 Agent 已完成计算 |
| 实际验证计算 | 确认可计算性、可比性、残差及复现边界 | 不用验证值替换论文目标；不称作信息受限的 Agent 盲测 |
| 历史 Agent 结果 | 检查评分协议能否读取交付物 | 不依据哪个 Agent 得分高调权重、选目标或拟合容差 |

阅读 verified_computation_reference.md 时先找有日期的最新验收段，再看历史。不要把旧 pending/failed 标签当当前状态，也不要把科学覆盖通过自动解释为全部出版问题已解决。

## 3. 建立论文—验证—评分证据表

逐篇读取正文、相关 SI 页和验证参考。每个候选评分项记录：

1. 科学作用：为什么该项能区分主要解释或支持重要结论？
2. 论文依据：文件、图表、1-based PDF 页序；与印刷页码不一致时同时写明。
3. 物理定义：分子/构象、原子映射、电子态、电荷/自旋、温度/溶剂、标准态、单位和能量零点。
4. 论文结果：数值目标或可明确判断真假的定性命题。
5. 实际验证：原生输入/输出或汇总位置、真实结果、偏差、已知限制。
6. 得分条件、分值，以及属于中间发现还是最终结论。

正文与 SI 冲突时，明确采用哪个定义及原因，不能挑更接近验证结果的一项。打印精度、标准态换算、构象集合和热化学校正的差异应先解释，再决定是否属于容差。

来源或原生结果不足时如实记录。已有合理目标和可比验证，只是尚无专家误差窗口，可以按本指南拟定初步 benchmark 容差，不必永久冻结整题。真正不能确定目标、物理身份或参照的情况仍需人工处理，不能用大容差掩盖。

## 4. 定性规则：明确、可证伪、有计算支持

按“对象—科学命题—实际证据—适用边界”编写。

合理示例：

- A 的完整 Cl− 复合物支持同一供体上两个有方向性的 I···Cl 接触。依据实际复合物几何/相互作用，不强设通用距离阈值，也不以含两个 I 原子代替结果。
- 相同中间体参照下，第二次无水 PT 与 ET 均上坡，且 PT 少吸能。检验符号和顺序，不再次要求精确命中两个数值窗。
- 干湿对照支持水尤其稳定 ET 离子端点，改变 PT/ET 热力学竞争。不能仅凭“水促进反应”一句话得分。
- 最终选择正确通道并给出计算支持的理由。算到了正确候选但最终未选择，不能获得该结论分。

完成若干次工具调用、用了某软件、写了局限性段落、充分探索、报告很完整，都不是科学发现，不能改个名称保留过程分。

证据资格是科学结果成立的前提，不是额外奖励。例如 TS 要有与目标反应相关的鞍点/连接证据；正常退出但物种错误的作业不能通过。普通计算失败不等于伪造，一个局部失败不应抹去其他独立结果。

## 5. 数值规则和容差

### 5.1 先保证物理等价

区分电子能、焓、Gibbs 自由能；绝热/垂直、局部/累计、势垒/绝对高度；核对构象、电子态、水数、组成、单位和标准态。物理对象错误，即使数字接近也不通过。

允许透明的单位和标准态换算，不允许为接近答案拟合偏移。验证使用的软件不自动成为任务硬约束。

### 5.2 维护者可提出初步容差

用户允许根据论文、真实验证计算和专业判断，为特定结果给出合理绝对容差。记录论文目标、验证值与残差、采用容差、理由及适用范围。

考虑论文精度、可比计算重复性、构象/低频热项敏感性、溶剂/模型差异，以及需要分辨的科学差异。相近物理量尽量使用少数一致类别，避免逐值拟合。

以下为已批准示例，不是所有任务的默认值：

| 场景 | 示例容差 | 物理前提 |
|---|---:|---|
| 2a71 七个匹配构象的 Cl− 结合自由能 | ±1.0 kcal/mol | 统一来源 raw 口径；1 M 差异单独换算 |
| c499 局部 PT/ET（除双水 ET） | ±1.0 kcal/mol | 同一局部参照与正确态 |
| c499 双水 ET | ±1.5 kcal/mol | 水合定义、构象处理一致 |
| c499 累计 I/F 自由能 | ±2.0 kcal/mol | 不能把累计量当单步增量 |

这些是初步 benchmark 验收政策，不是作者误差条、统计置信区间或所有 DFT 方法的统一精度。不要用“当前最大误差＋很小余量”倒推窗口，不按某个 Agent 的失败结果不断放宽。专家可修订后续版本，旧评分保留版本和快照。

### 5.3 定量和定性独立

定量判断为绝对差小于或等于容差，边界包含。target/tolerance 由规则文件固定，宿主计算，Judge 不临时改变。

数字超窗但正确趋势仍有有效计算支持，可以得到独立定性项；数值落窗但排序反转，不能得到正确排序/最终选择分。尤其不能用重叠窗口命中替代相对排序判断。

不要求每个定性命题有精确数值阈值。ESP 最大值、原子电荷和很小构象能差，可按定义相容的方向、分布或可达性评价，不勉强制造统一阈值。

## 6. 权重与粒度

每篇合计恰好 100。中间/最终是科学角色，定量/定性是判定方式，两个维度不要混淆。

- 解释型任务优先给结构、比较和综合解释足够权重；数值是证据的一部分。
- 明确以计算竞争势垒为核心的问题，可以有较高定量权重，不强制所有任务相同比例。
- 一个科学主张只奖励一次。数值、相对比较、跨性质最终解释可以分别评分，但要写明新增科学信息。
- 含多个可独立完成对象时拆成二元子项。例如 A/C/D 双点结合拆成 4/3/3 分，不保留一个 10 分项却让 Judge 自由给部分分。
- 不按条数平均分，也不按现有 Agent 成绩决定权重。

V2 每个叶子项满足全部条件得满分，错误或缺失得 0。部分完成通过预先拆项体现，不让 Judge 即兴给比例分。

## 7. 修改文件与协议

优先只改任务数据，不增加按论文 ID 分支的评分代码。

| 文件 | 维护内容 |
|---|---|
| evaluation/reference_key_points.json | 中间发现 ID、命题、证据、范围 |
| evaluation/reference_conclusions.json | 最终结论及支持的关键点 |
| evaluation/scoring_rules.json | scoring_policy 为 paper_science_v2；具体规则、100分 scientific_rubric、统一科学要求 |
| evaluation/evidence_map.json | 来源路径、SHA-256、PDF 页序 |
| evaluation/critical_failures.json | 伪造/隐藏答案泄漏等有效性问题；普通失败按项计分 |
| evaluation/reference_qualification.json（如有） | 当前运行评分资格与出版待审分开；解除已批准规则所取代的旧冻结 |
| evaluation/verified_computation_reference.md | 保留历史计算事实；必要时加现行评分状态说明 |
| package_manifest.json | 重算大小、逐文件哈希和包哈希 |

删除活动规则中的过程 rubric、倍率、效率分、预算/调用/失败诊断得分和只供旧双轴使用的字段。历史审计保留并明确非现行评分。核心规则、关键点、结论不得残留矛盾的冻结或旧权重。

原生 scientific_rubric 每项使用 id、kind（intermediate/conclusion）、max_score、description、rule_ids、evidence_ids。规则有 rule_id、reference_id、type、expected、binding；numeric 另有有限的 target、非负 tolerance、unit。参考本目录两篇已更新任务，不自行发明 schema 字段或修改引擎来适配单篇论文。

## 8. 实施顺序与测试

1. 读取任务和现行评分实现，记录 Git 状态，只备份/修改授权范围。记录全部 agent_input 的 SHA-256。
2. 建立来源证据表，确认每项科学含义及物理定义。
3. 分配中间/最终、定量/定性、独立子项和初步容差，记录理由。
4. 同步 evaluator 文件，移除被新政策取代的活动阻塞；保留真实科学边界。
5. 使用 package_payload_entries、package_content_hash 刷新 manifest，不猜测哈希。
6. 在支持的布局验证包。small_molecules_verified_autonomous_research 是维护源目录，应复制到临时 autonomous_research/<paper_id> 或受支持 final 布局后验证/加载。目录类型错误不是规则内容错误。
7. 运行 tests/test_small_molecules_paper_science_v2.py、tests/test_paper_science_v2.py 及必要回归。
8. 检查总分100、ID唯一、所有规则/来源关联有效、同时含中间/最终、公开文件哈希不变。
9. 测试目标、正负容差边界、略超边界、错误单位/身份、无证据、单项失败、缺失最终结论；定量失败不得误伤独立定性项。
10. 验证已合格任务可进入 Judge，真正未合格参考仍被阻断。新任务用新规则；历史/resume 用冻结规则。

控制 Judge 返回的测试只证明协议和计分，不等于真实 Agent 实验或在线 Judge 成绩。复用验证数值不是新做量子化学计算，汇报要明确测试层级。

## 9. 专家交接

每篇提供科学问题/范围、完整现行题面、输入/交付索引、逐项分值及条件、设计理由、论文图表/PDF页、验证结果/残差、参考定义/限制、专家待确认问题。

来源正文和相关 SI 与报告一并提供。未打包的原生日志明确服务器位置。历史与活动规则分开。任务副本与维护源逐字节一致，不能为修链接悄悄改副本合同。

专家意见按规则 ID 记录：认可/修改/删除、目标定义、容差/分值、论文依据和理由。交付说明文件变化、评分可用性、出版待审限制、测试结果和 ZIP 路径。
