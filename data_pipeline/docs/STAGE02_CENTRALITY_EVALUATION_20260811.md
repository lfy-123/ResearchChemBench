# Stage02 Computational Centrality Evaluation (2026-08-11)

## Objective

Stage02 must retain only two high-precision classes:

- `computational_content_confirmed`: original pure computational chemistry with no new author physical experiment.
- `computational_primary_mixed_confirmed`: computation produces the paper's primary scientific contribution and author experiments provide limited validation or support.

It rejects experiment-led papers even when DFT, MD, or another calculation is important to a mechanistic subclaim.
The key counterexample is a newly synthesized catalyst whose activity is measured experimentally and rationalized
afterward by DFT: losing the DFT explanation does not erase the experimental headline result.

## Frozen Evaluation Set

The evaluation uses 200 papers from `runs/stage00-03-random500-seed20260810`. Main-paper and SI normalized text
paths and SHA256 values are frozen in `runs/stage02-eval-200-20260811/manifest.jsonl`.

This is a stratified historical challenge set, not a random prevalence sample. Its pass rate must not be interpreted
as the expected yield of the remote corpus.

Reference labels were produced independently from the Stage02 model run by three gpt-5.6-sol annotation agents. The
annotation process recorded 397 exact quotes; every quote was checked as a continuous substring of the frozen main
paper or SI text. Fourteen low-confidence papers received a second blind gpt-5.6-sol label. Nine disagreements or scope inconsistencies were explicitly adjudicated and are
stored in `reference_audits/adjudications.jsonl`. The evaluator applies these adjudications without replacing the raw
independent labels.

Final reference distribution:

| Class | Papers |
|---|---:|
| Pure computational | 13 |
| Computational-primary mixed | 9 |
| Experimental-primary with computational support | 123 |
| No substantive computational chemistry | 55 |

The reference set is an expert-model-assisted audit set, not a conventional multi-human gold standard. Metrics should
therefore be interpreted together with the paper-level evidence and adjudication record.

## Implemented Cascade

1. Stage01 must successfully parse the main paper and every known SI document. Partial packages do not enter Stage02.
2. A deterministic rule pass builds a balanced, bounded evidence packet from title/abstract/conclusion, computational
   passages, experimental passages, main paper, and SI.
3. Obvious papers with no substantive computational signal are rejected without a model call.
4. Qwen3-30B-A3B-Instruct-2507 performs one five-class centrality decision.
5. Only a proposed Pass receives a second, compact adversarial call. This verifier tries to prove that the headline
   result was actually generated by synthesis, measurement, material fabrication, or physical performance testing.
6. Deterministic experiment extraction is positive-only evidence. Its empty result is no longer treated as proof that
   the authors performed no experiments; model-cited experiment evidence must resolve to supplied evidence IDs.
7. Schema diagnostics do not automatically become scientific uncertainty. A consistent pure/mixed label mismatch is
   repaired from the author-experiment axis, while unsupported or low-confidence Pass decisions become `uncertain`.
8. Every response, evidence ID, decision, warning, model request audit, and cache hash is retained per paper.

The primary input budget is 24,000 characters, with a 2,048-token output ceiling. The Pass verifier uses a 768-token
ceiling. The 24,000-character budget eliminated the only observed Qwen 16K-context failure without removing the
paper's central narrative and computational evidence.

## Final Results

The final run used the user-provided H200 worker, 32 concurrent requests, and the same frozen 200-paper set.

| Metric | Initial r7 | Final |
|---|---:|---:|
| Model calls | 370 | 209 |
| Processing failures | 1 | 0 |
| Hold rate | 63.0% | 27.5% |
| Pass precision | 25.5% | 100.0% |
| Pass recall | 44.4% | 63.6% |
| Pass F1 | 32.4% | 77.8% |
| Exact five-class accuracy | 18.6% | 62.5% |

The initial r7 metrics used the pre-adjudication reference snapshot, so the table is primarily an operational and error
trend comparison. Final metrics use all nine recorded adjudications.

Final prediction distribution after mapping non-original articles to no computational content:

| Prediction | Papers |
|---|---:|
| Pure computational Pass | 12 |
| Computational-primary mixed Pass | 2 |
| Experimental-primary reject | 100 |
| No substantive computation reject | 31 |
| Hold (`uncertain`) | 55 |

All 14 final Pass papers were individually checked against their reference evidence and model rationales. No
experimental-primary or no-computation paper was passed.

Per-Pass-class recall remains asymmetric:

- Pure computational: 12/13, 92.3% recall, 100% precision.
- Computational-primary mixed: 2/9, 22.2% recall, 100% precision.

The first complete r8 run took 169.7 seconds. The final verification run took 27.1 seconds because unchanged model
requests were replayed from the local cache; only 11 HTTP requests were needed. The cold-run time is the representative
number for a new 200-paper set.

## Remaining Errors

The remaining eight Pass false negatives are:

- `stage02-eval-0026`: dispersion-driven catalyst design, classified conservatively as experiment-led/Hold.
- `stage02-eval-0055`: ML over an original metal-cluster reactivity dataset, classified experiment-led.
- `stage02-eval-0101`: computational screening followed by conductor validation, held after inconsistent output.
- `stage02-eval-0105`: computed lithiophilicity descriptor plus material validation, classified experiment-led.
- `stage02-eval-0111`: MD-guided W113A enzyme design, held after inconsistent output.
- `stage02-eval-0159`: computation-only explanation of prior photosystem experiments, held because the phenomenon was
  previously observed.
- `stage02-eval-0178`: coupled microkinetic model and product probing, classified conservatively as experiment-led.
- `stage02-eval-0196`: multiscale ceria surface model with complementary measurements, held/experiment-led.

These failures share a real semantic boundary: computation produces a model, descriptor, design rule, or intervention,
while original experiments supply data or validation. The current Qwen model favors rejecting such papers. Adding
keyword exceptions would overfit this evaluation set and violate the pipeline's generality requirement.

For the stated high-precision objective, the conservative result is acceptable. If higher mixed-paper recall is later
required, the recommended change is a stronger-model review only for `uncertain` and experiment-led papers whose model
record identifies a complete computation. It should use the same frozen evidence and produce a separately audited
decision; the deterministic rule layer should not be expanded with paper-specific patterns.

## Reproduction

Run the frozen evaluation with an existing managed worker state:

```bash
.envs/researchchem-data-pipeline/bin/python scripts/evaluation/run_stage02_eval.py \
  --evaluation-root runs/stage02-eval-200-20260811 \
  --source-run runs/stage00-03-random500-seed20260810 \
  --worker-state runs/stage02-eval-200-20260811/.screening_llm_worker.local.json \
  --workers 32
```

Then generate paired records, disagreements, metrics, and the compact report:

```bash
.envs/researchchem-data-pipeline/bin/python scripts/evaluation/analyze_stage02_eval.py \
  --evaluation-root runs/stage02-eval-200-20260811 \
  --sampling-audit runs/stage02-eval-200-20260811/sampling_audit.private.jsonl
```

The user-owned external worker is intentionally left running for later tasks.
