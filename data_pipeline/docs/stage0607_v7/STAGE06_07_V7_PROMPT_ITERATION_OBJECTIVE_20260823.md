# Stage06/07 v7：十五轮通用 Prompt 优化总目标

日期：2026-08-23（预算调整：最多 15 轮）  
基线目标：[Stage06/07 v6 Prompt 优化总目标](../stage0607_v6/STAGE06_07_V6_PROMPT_OPTIMIZATION_OBJECTIVE_AND_BOUNDARIES_20260822.md)

## 1. 目标

在最多十五轮迭代中，主要优化 Stage06A、Stage06B、Stage07 的角色 Prompt，使它们在不同模型上都能按职责工作。每轮只解决可复现的共性 Prompt 问题；不根据单篇论文、固定数值、分子、软件、文件名或答案添加特例规则。

本轮不以科学批准率为目标。合理的科学拒绝、转换不确定和发布任务都属于有效终态；评价重点是角色边界、证据链、任务代表性、模式隔离、合同状态和运行可解释性。

## 2. Prompt 边界

- Stage06A 选择论文完整计算主线；只有在复杂度、成本、源数据或科学闭合性有证据阻断时，才退到最重要的核心子流程；无法构建有意义的完整路线或核心子流程时拒绝。
- Stage06B 只做答案盲的 autonomous 公共面转换，不重新选题、不重写 Ground Truth、不接触 hidden answer。
- Stage07 按“科学审计 → 证据支持的修复 → 修复后最终复核/决定”顺序工作；不猜测缺失科学事实。
- 代码负责运输、schema、路径、manifest、发布状态和可观察性，不承担化学裁决。
- autonomous 的公开边界、方法约束和验收语义必须自洽；方法发现型任务不能使用只对隐藏作者方法成立的严格绝对目标。
- Prompt 保持简洁、分层、术语一致，删除重复或由代码保证的指令，不堆叠示例和固定检查表。

## 3. 每轮测试协议

每轮从 Stage05 通过集合中随机抽取 10 篇互不重叠的论文：

- 5 篇由 `deepseek-v4-pro-0813` 合成；
- 5 篇由 GPT 模型合成；
- 两组使用完全相同的 Stage06/07 Prompt、Codex harness、推理强度和可比并发配置；
- 每轮记录随机种子、论文 ID、模型实际 ID、commit、配置、运行目录和失败分类；不静默替换样本。

当前测试模型明确为 `gpt-5.6-sol`，不是 `gpt-5.6-pro`。本地 GPT API 的 `/v1/models` 已确认包含 `gpt-5.6-sol`；DeepSeek 使用 `deepseek-v4-pro-0813`。两者均按实际模型名记录，不做替代或冒充。

## 4. 每轮分析

逐篇记录 Stage06A 选题、Stage06B 脱敏、Stage07 科学审计/修复/决定、机械状态和最终发布状态，并区分：

- 代码 bug；
- Prompt/角色职责问题；
- 模型能力或工具调用差异；
- 论文源材料不可执行或科学上合理的拒绝。

重点比较完整路线/核心子流程代表性、输入和参考态闭合、软件缺口登记、答案盲隔离、审计与最终决定一致性、机械误阻断和公共泄漏。发布率不是唯一指标。

## 5. 停止条件

最多十五轮；若已经没有可重复的通用 Prompt 歧义、角色越权或代码运输 bug，且两个模型的剩余差异可以归因于模型能力或源材料，则可提前停止。若达到十五轮仍只有零散模型遗漏，不追加无限规则，记录为模型能力限制。
