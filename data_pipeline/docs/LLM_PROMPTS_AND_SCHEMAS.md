# LLM 职责与输出约束

运行时 prompt 的唯一权威来源是 `src/prompts.py`；本文件说明阶段职责和不可跨越的边界，避免
文档复制的长 prompt 与代码漂移。

## Stage02：计算化学内容

Stage02 使用 map-reduce。Map 输入是 Stage01 产生的正文和全部 SI 内容块，包括文档角色、章节
路径和稳定 evidence ID；优先发送标题、摘要、方法、计算细节、结果和 SI 计算章节，并对总字节数
设硬上限。Map 只抽取当前论文作者实际执行的计算步骤、方法、软件线索、目标量和作者实验线索。

Reduce 输入只包含已验证 evidence ID、短原文引用、文章类型元数据和 map 摘要。它输出论文类型、
计算范围、方法族、工作流完整性、作者实验状态、置信度、判定和理由。只有完整的纯计算化学原创
研究可以通过；当前作者进行过物理实验的论文即使以计算为主也不通过。模型不得以“提到 DFT”或
引用他人工作作为通过依据；所有肯定结论必须能回指输入 evidence ID。

## Stage03：软件、工作流和资源

输入由 Stage02 已确认的计算证据、相关方法章节、规则/Softcite 软件候选和冻结工具箱快照组成。
模型负责建立论文实际工作流，区分核心计算、必需前后处理、可选分析、可视化、仪器软件和背景
引用，并抽取明确报告的资源事实。它不直接决定工具箱覆盖。

确定性 resolver 使用 `assets/toolbox_capabilities.json` 和软件别名映射模型输出。通过含义是论文
所需的命名核心软件存在于工具箱原生软件目录；不要求存在预设 Action，也不把通用 Python 处理
误判为缺失软件。未命名核心引擎、清单不完整和工具箱外核心软件必须保留为不同判定。

## Stage05：Benchmark 适用性

输入是 MinerU 高质量文本、Stage02 计算证据和 Stage03 已解析工作流。模型判断是否存在完整科学
问题、可提供的输入、可执行计算过程、可隐藏的参考结果及机器可评分目标，并映射到允许的十个
科研方向。输出 0-3 个候选；简单读取、重绘或抄录论文答案不能作为候选任务。

## Stage06/07：构建与审核

Stage06 先生成共享科学记录，再分别生成自主科研和论文复现任务。公开输入不得包含隐藏答案、
论文定位路径或直接泄漏目标的结果。所有目标、结构和参数必须引用冻结证据。

Stage07 使用独立模型审查科学正确性、可执行性、工具箱可用性、证据完整性、评分客观性和信息
泄漏。模型输出之后仍执行确定性 schema、路径、引用和可选 Gold Run 检查。

## 通用调用契约

- 请求保存模型完整名称、endpoint、温度、seed（若支持）、最大 token、prompt 版本和输入 hash。
- 保存原始响应、解析结果、finish reason、响应 hash、重试和错误。
- JSON 截断只允许触发有限重试或最小修复调用，不允许把缺字段响应默认为通过。
- 严格复现依赖缓存回放；远程模型新调用只要求结构和判定语义在允许范围内一致。
- 单篇调用失败写入 `processing_errors.jsonl` 并隔离，不使整个批次丢失已完成结果。
