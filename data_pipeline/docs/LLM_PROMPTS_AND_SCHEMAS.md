# LLM 职责与输出约束

运行时 prompt 的唯一权威来源是 `src/prompts.py`；本文件说明阶段职责和不可跨越的边界，避免
文档复制的长 prompt 与代码漂移。

## Stage02：计算化学内容

Stage02 先在本地扫描 Stage01 产生的正文和全部 SI 文本块，不调用模型完成关键词裁决。本地检索器
按正文叙事、计算证据和作者实验依据三类构造平衡证据包，并保留文档角色和稳定 evidence ID。只有
全文没有实质计算信号时才零调用淘汰；其余论文默认进行一次 paper-level 模型裁决。

模型输出计算工作流、生成结果、科学用途、作者实验、计算主次和双向反事实，同时输出证据方向：
纯计算、计算预测后由实验验证、实验观察后由计算解释、共同依赖或不确定。主次关系只作为数据集
元数据，不再作为硬淘汰条件；实验主导论文只要含有完整、非平凡且能分离为有意义子任务的计算流程，
也可以进入 Stage03。
高精度全文规则发现的作者实验原句也放入模型可见证据包。程序分别验证计算、实验和叙事 evidence ID；
程序验证计算、实验和叙事 evidence ID，并区分纯计算、计算主导混合、计算与实验共同主导、实验
主导但计算流程可构建、计算流程不足、无计算内容和不确定。每篇有计算信号的论文进行一次独立短
复核；复核不读取首轮答案，只根据原始证据判断化学模型、实际计算、生成输出、科学用途、非平凡性
以及是否仅为实验数据处理，永不进行第三次调用。前四类进入 Stage03；流程不足和
无计算内容淘汰；证据不足进入 Hold。模型不得按计算段落篇幅、SI 细节数量或单独出现的软件/DFT
名称判断流程完整性。复核负责是否通过，首轮负责纯计算/混合研究的角色标签；作者实验轴不确定时
不得否定已经完整确认的计算流程。

## Stage03：软件、工作流和资源

输入由 Stage02 已确认的计算证据、相关方法章节、规则/Softcite 软件候选和冻结工具箱快照组成。
模型负责建立论文实际工作流，区分核心计算、必需前后处理、可选分析、可视化、仪器软件和背景
引用，并抽取明确报告的资源事实。它不直接决定工具箱覆盖。

确定性 resolver 使用 `assets/toolbox_capabilities.json` 和软件别名映射模型输出。通过含义是论文
所需的命名核心软件存在于工具箱原生软件目录；不要求存在预设 Action，也不把通用 Python 处理
误判为缺失软件。仅 `software_covered` 和 `software_coverage_probable` 进入 Stage04。未命名核心
引擎、混合覆盖和工具箱外核心软件仍保留为不同审计判定，但不继续进入后续阶段。

## Stage05：Benchmark 适用性

输入是 MinerU 高质量正文和全部 SI、Stage03 已解析工作流、冻结的软件覆盖事实和资源预算。
正文与每个 SI 独立分配证据预算，避免正文截断导致 SI 从 prompt 消失。模型判断是否存在完整
科学问题、已提供的输入和参数、可执行计算过程、可隐藏的参考结果、机器可评分目标及可辩护的
成本，并映射到允许的科研方向。每篇只输出 0 或 1 个最强候选；简单读取、重绘、抄录论文答案、
为了凑步骤而拼接昂贵下游流程都不能作为候选任务。

软件覆盖事实不可由模型改写。`catalog_present=true` 表示原生软件调用可用，不要求预设 Action；
模型只能把确定性 resolver 列入 `uncovered_required_software` 的名称写入 `blocking_software`。
软件清单未确认时可以把 `software` 作为阻断维度，但不能捏造软件名。输出必须包含结构化
`blocking_dimensions`、`blocking_software`、成本估计和五项 buildability 检查；事实或契约冲突
触发一次修正调用，仍冲突则记为 `contract_invalid`，不得静默通过或淘汰。

## Stage06/07：构建与审核

Stage06 先生成共享科学记录，再分别生成自主科研和论文复现任务。公开输入不得包含隐藏答案、
论文定位路径或直接泄漏目标的结果。所有目标、结构和参数必须引用冻结证据。

Stage07 使用独立模型审查科学正确性、可执行性、工具箱可用性、证据完整性、评分客观性和信息
泄漏。模型输出之后仍执行确定性 schema、路径、引用和可选 Gold Run 检查。

## 通用调用契约

- 请求保存模型完整名称、endpoint、温度、seed（若支持）、最大 token、prompt 版本和输入 hash。
- 保存原始响应、解析结果、finish reason、响应 hash、重试和错误。
- JSON 截断只允许触发有限重试或最小修复调用，不允许把缺字段响应默认为通过。
- 严格复现依赖缓存回放；远程模型新调用只要求结构和判定语义在允许范围内一致。
- 单篇调用失败写入 `processing_errors.jsonl` 并隔离，不使整个批次丢失已完成结果。
