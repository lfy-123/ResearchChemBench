# Stage06/07 v5 优化总目标、边界与迭代验收

版本：v5  
日期：2026-08-21  
范围：Stage06A、Stage06B、Stage07，以及在满足条件时新增的 Stage07B。Stage00–05 不在本轮修改范围内。

## 1. 总目标

把 Stage06/07 稳定为一个通用的论文计算任务合成与审计流程。验收重点是角色边界、合同闭合、信息隔离和代码可靠性，而不是要求每一篇论文都得到科学批准或发布。

一个科学拒绝、输入不足或源材料不可执行的结果可以是正确结果；只有把这类科学结论错误地改写成代码拒绝，或因代码合同 bug 误阻断/误发布，才算流程缺陷。

## 2. 科学范围选择原则

- 默认优先覆盖论文的完整核心计算路线。
- 只有在有证据表明整条路线成本过高、关键数据缺失、软件/资源不覆盖或过程无法闭合时，才退回到最重要的核心子过程。
- 选择子过程时记录覆盖的科学主张、排除的主张、在原路线中的位置和选择理由；不得因为任务更容易包装而随意截取。
- 输入闭合、参考态、物理边界、计算动作和验证标准属于科学审计内容，由 Stage06A/Stage07 Agent 根据论文与补充材料判断；代码不得用论文、分子、固定数值或关键词猜测这些内容。

## 3. 角色职责

### 3.1 Stage06A：科学任务构建

负责阅读论文/SI、选择范围、构建复现任务草稿、列出输入资产/参考态/workflow/过程 Key Points/最终结论草稿，并输出 workflow completeness check 和供审计使用的私有资产映射。不能猜测缺失科学信息，也不拥有最终批准权。

### 3.2 Stage06B：答案盲自主表面转换

负责把复现草稿转换为自主公共表面：隐藏作者路线、方法选择和答案泄漏，采用中性资产名和字段名，同时保留提出问题所必需的结构、组成、实验事实及物理边界条件。不能重新选择科学 workflow、改动 Ground Truth 数值/结论/排序/容差，不能看到或公开答案性源材料。

### 3.3 Stage07：科学审计与科学修复

负责审计科学目标、输入/参考态闭合、计算动作与验证标准相容性、Key Points/最终结论以及两个模式的信息隔离和 evaluator binding 语义。能够依据源论文/SI和 Stage06A 的私有映射修复有证据支持的问题；无法闭合时做科学拒绝。Stage07 的科学决定不由机械 gate 替代。

### 3.4 编排器/代码

只处理文件和目录运输、确定性 ID、最小 JSON/schema/evaluator 合同、路径安全、manifest、发布隔离和可观察状态。机械 gate 只能产生可解释的 transport finding，不做物质平衡、溶剂正确性、化学可行性或答案语义裁决，也不能把 Agent 的科学批准改写成科学拒绝。

## 4. 任务合同和信息隔离

1. `task.md` 是唯一给被评估 Agent 的任务指令。`task_info.json`/`task_spec.json` 只保存简短元数据和机器合同，不能形成第二套科学指令；不新增或依赖 `task_info.task` 作为指令来源。
2. 复现模式可以公开论文路线、软件、方法、参数、溶剂和验证操作，但不得公开评分答案、目标数值、排序、偏好路线、结论或容差。
3. 自主模式可以保留定义科学问题所需的输入事实和物理边界；隐藏作者实现路线和方法选择，除非方法本身就是公开的科学变量/边界条件。公开 Key Point 只能使用中性 alias（例如 `kp_001`），不得公开 `gt_*`、`canonical_answer` 或内部 acceptance profile ID。
4. `hidden_reference/ground_truth_common.json` 是 private scientific truth 的唯一权威来源。其他 registry/evaluator 文件只能由代码从它投影生成，不允许手工维护互相漂移的科学副本。
5. `route_evidence_map.json` 只保存 evidence ID、路线步骤/类别索引等安全索引；目标数值、答案排序、结论、DOI、源文件路径和原文答案段落留在 private/source evidence，不进入公共 route map。
6. 两个模式可以使用不同的匿名文件名、字段名和结果表示，但必须共享同一科学问题、输入事实、Key Point 语义和 private truth；适用模式不同的 Ground Truth/profile/binding 是合法的，代码不得把它们强制扩大为双模式。

## 5. Key Points 与评分边界

数据管线只负责定义本任务需要交付的过程 Key Points 和最终结论结果，以及每项对应的证据/类型/binding。Key Point 数量、结论数量和 rubric 组织按任务内容决定。

数据管线不统一规定 `binary`、`dual_axis_100`、总分 100 或任何具体评分公式；也不因缺少某种评分模式字段而替代科学审计。若下游 evaluator 需要额外评分合同，由 evaluator/发布层单独定义和验证，不回写成 Stage06/07 的科学规则。

## 6. Stage07B 的可选设计边界

Stage07B 不是默认阶段。只有在先修复通用 gate/合同 bug 后，测试显示：Stage07 已经科学批准，但仍有“很多”论文因相同或相近、可由现有信息确定修复的简单合同问题无法发布，且让 Stage07 重做会明显浪费 token 时，才启用窄 Agent。建议把“很多”操作化为一个 10 篇样本中至少 2 篇出现同类可机械修复阻断，或连续两批重复出现；该数值是工程触发信号，不是科学规则，启用前应在迭代记录中给出证据。

若启用，Stage07B 只允许：

- 修复路径、文件名、字段类型/容器、明确的 mode binding、rubric 包装和脱敏映射等 transport 合同；
- 使用 Stage07 的 immutable scientific audit 和私有 ID 映射，不重新阅读/改写科学结论；
- 一次修复、一次机械复检；无法确定则输出 `mechanical_blocked_unresolved`，不得强行发布。

Stage07B 不得新增/删除科学 Key Point，不得改变 workflow、Ground Truth 数值、结论、排序或容差，也没有科学批准权。

## 7. v5 迭代计划与验收

最多五轮。第一轮先修复已确认的通用问题：

1. evaluator profile 按 `applies_to_modes` 正确过滤；
2. mode-specific binding 解析只在适用 mode 中检查，并保留旧输入读取兼容、规范输出单一；
3. Stage06 hidden validator/normalizer 保留 profile/truth 的合法 mode scope，不再无条件覆盖为双模式；
4. 去除数据管线对统一评分模式/总分的强制，保留 Key Point/结论完整性检查；
5. route evidence map 采用安全索引投影；
6. 公开自主 Key Point 使用中性 alias；
7. 记录机械 normalization 的 provenance，避免 Agent 原始输出与发布树的差异不可追溯。

每轮均须：

- 以 Git 提交只涉及本轮的 Stage06/07代码、测试和文档；
- 运行全量 Stage06/07 单测，再用 DeepSeek-v4-pro-0813 从既有 Stage05 通过论文中随机抽取 10 篇、并发 10 测试；
- 逐篇区分代码 bug、Prompt/角色边界问题、模型能力限制和源材料不可执行问题；
- 对照本文件第 1、3、4、5、6、8 节记录结果，不因个别论文表现增加特例规则；
- 只有在 10 篇测试不再出现明显共性合同问题后才停止，或在五轮内达到“代码无稳定共性 bug、角色职责清晰、科学拒绝可见且不被强行发布”的目标。

最终不能出现：论文/分子/固定答案特例、匿名化导致的机械误报、科学批准与机械状态混淆、公共任务答案泄漏、Stage07B越权或 Stage00–05 数据被改写。
