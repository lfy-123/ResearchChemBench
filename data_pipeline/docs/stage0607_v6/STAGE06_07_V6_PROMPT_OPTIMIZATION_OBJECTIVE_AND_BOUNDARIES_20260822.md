# Stage06/07 v6 Prompt 优化总目标与边界

版本：v6.0 目标稿
日期：2026-08-22
基线：Stage06/07 v5 Round 20 代码与审查结果
范围：Stage06A、Stage06B、Stage07 的角色 Prompt、Prompt 合同测试和十轮模型回归；不修改 Stage00–05。

## 1. 本轮总目标

在不增加论文特例、化学关键词规则、固定答案规则或过度示例的前提下，重新组织 Stage06A、Stage06B 和 Stage07 的 Prompt，使三个角色能够更稳定地完成各自职责，并使相同 Prompt 在不同模型上具有一致、可解释的行为。

本轮的成功标准不是让更多论文被批准，也不是让两个模型产生相同的任务。正确的结果可以是批准、科学拒绝、转换不确定或可见的运行失败；关键是结果应当由正确的角色依据正确的证据作出，代码不能把科学不确定性伪装成确定性结论。

本轮重点解决 v5 Round 20 暴露的通用 Prompt 问题：

- Stage07 Prompt 过长、职责跨度过大，模型在完成修复后容易漏掉最后的局部一致性检查；
- 科学审计、文件修复和最终批准混在同一条长指令中，审计结果与修复结果可能相互污染；
- autonomous 模式的方法自由、物理边界和绝对数值验收之间的关系表达不够清楚；
- Stage06A/Stage07 的同一科学要求在多个段落重复或使用不同措辞，模型可能把优先级理解反；
- Prompt 已经提出的电子态、输入闭合、中心性和模式绑定检查，未被稳定地落实到最终审计中；
- 不同模型在工具调用、拒绝阈值和局部一致性检查上的差异，尚未被清楚区分为 Prompt 问题、模型能力问题或源材料问题。

## 2. Prompt 设计原则

### 2.1 简洁、分层、无冲突

每个角色 Prompt 只保留完成职责所必需的四类内容：

1. 角色目标和权限边界；
2. 输入、输出和状态合同；
3. 少量按优先级排列的审查/转换步骤；
4. 完成前必须报告的最小证据。

删除重复的原则性段落、已经由代码保证的文件运输说明、互相覆盖的旧字段别名和不会改变决策的叙述性要求。不同角色之间的同一概念使用相同术语；若两个模式存在合法差异，明确说明“共享科学语义、允许不同公开表示”，不再用相互矛盾的旧表述解释。

### 2.2 通用表述优先于案例规则

Prompt 不得加入特定论文、分子、软件、数字、文件名、历史失败样本或人为答案。不得把某一次测试中发现的化学事实改写成所有任务都必须满足的字符串规则。

允许使用抽象的科学类别，例如“输入状态”“电子态”“几何敏感目标”“直接计算证据”“支持性证据”“模式适用性”和“源材料证据”，但这些类别只用于要求 Agent 进行审计和说明，不用于让代码自动裁决化学正确性。

### 2.3 科学决定与运输决定分离

Prompt 只要求 Agent 形成科学判断和结构化证据；代码继续负责文件、schema、路径、manifest、发布状态和可观察性。机械 gate 不扩展为化学审计器。

如果 Agent 发现输入不足、电子态冲突、参考态不闭合、目标与方法不相容或科学主线无法构建，应形成有证据的科学拒绝或不确定状态；不得为了满足发布合同而猜测科学事实。反过来，文件类型或路径问题也不能被描述成论文科学不可执行。

## 3. 三个角色的 Prompt 目标

### 3.1 Stage06A：选择和构建科学任务

Stage06A 的 Prompt 应让 Agent 按以下逻辑工作，但不要求使用冗长固定模板：

1. 先盘点论文中与主要科学问题相关的计算化学路线；
2. 默认选择能够覆盖论文主要计算主线的完整范围；
3. 只有在完整路线过于复杂、成本不可辩护、关键数据缺失或路线无法闭合时，才选择最重要且可闭合的核心子过程；
4. 如果完整路线和最高中心性的核心子过程都不能在不猜测关键科学事实的情况下构建，则科学拒绝，不用外围、容易包装的分支凑任务；
5. 缺少当前工具箱软件只登记为资源缺口，不作为缩小范围或科学拒绝的独立理由；
6. 为所选范围提供足够的主张覆盖、输入闭合、参考态、计算动作、验证方式和资源依据，使 Stage07 可以复核，但不把最终批准权交给 Stage06A。

Prompt 应明确区分：科学身份/连接关系、可构建的初始模型、作者实际使用的源计算状态、确定性搜索过程和对目标敏感的唯一结构。不得把“可以生成一个模型”直接等同于“能够复现作者结果”。

Stage06A 只构建复现草稿和私有审计交接，不生成权威 autonomous 公共任务，也不修改 hidden truth。

### 3.2 Stage06B：答案盲的 autonomous 公共面转换

Stage06B 的 Prompt 应保持窄职责：

- 只转换 public surface，不重新选择 workflow，不评价科学中心性，不修订 Ground Truth；
- 保留定义问题所必需的输入事实、边界条件和可执行交付要求；
- 隐藏作者路线、实现选择和答案性内容，使用中性资产名、字段名和公开 Key Point alias；
- 不把 private conversion packet、内部 ID、canonical answer、profile ID 或 handoff 说明写入公共任务；
- 遇到科学语义疑问时交给 Stage07，只有真实的文件/API/运行阻断才报告转换重试；
- 依赖编排器预置的公共任务树，不重复复制、展平或重建工作区。

Stage06B 的 Prompt 不应包含科学选题、答案推断、论文结论重写或工具箱可用性判断。其输出应足以让 Stage07 检查脱敏是否完成，但不向 Stage06B 暴露 hidden scientific truth。

### 3.3 Stage07：先审计，再修复，再决定

Stage07 是本轮 Prompt 优化的重点。Prompt 应把一次长任务明确分成三个顺序阶段：

1. **科学审计阶段**：冻结对 Stage06A 选题、论文主张覆盖、输入/参考态/电子态、计算动作、验证方式、资源可行性和模式验收口径的判断；
2. **修复阶段**：只根据已有源材料和私有映射修复可证实的问题，不能用猜测补齐结构、电子态、参考态、方法结果或答案；
3. **最终复核阶段**：重新阅读修复后的公开面、private truth 投影和 evaluator binding，确认修复没有改变科学语义，并让最终决定与审计结果一致。

Prompt 应要求 Agent 用紧凑的结构化审计记录表达以下关系，而不是在多个长段落中重复描述：

- 论文主要计算主张 → 直接计算证据 → 选定 workflow 的覆盖关系；
- 每个关键输入/参考态 → 其来源、用途和闭合状态；
- 每个差值、比较或机制结论 → 两端、物理边界、计算动作和证据来源；
- 每个 mode → 可公开的方法/边界、结果表示、适用 acceptance profile 和 binding；
- 修复前后的科学语义是否保持不变。

这些记录是 Agent 的审计证据，不是让代码根据化学字段自动判定对错的规则。矩阵字段应尽量少，且按实际任务内容生成，不设置论文无关的固定行数或固定 Key Point 数量。

### 3.4 autonomous 模式的 Prompt 口径

Prompt 必须明确区分两种合法情况：

- 方法受约束的 autonomous 任务：公开必要的方法/边界，允许使用方法相关的绝对目标；
- 方法发现型 autonomous 任务：不公开作者实现方法，验收重点应转为方法稳健的排序、趋势、符号、过程证据或其他与方法无关的结果表示。

不能同时使用“方法完全自选”的措辞和只有在某个隐藏论文方法下才成立的严格绝对数值目标。若源任务无法支持方法无关的验收，Stage07 应调整公开边界和任务说明，或者诚实地降低验收主张，而不是让两个模式共享不相容的隐藏评分口径。

## 4. 模型无关的十轮对比测试设计

### 4.1 每轮样本和模型

每轮从 Stage05 通过集合中随机抽取 10 篇论文：

- 5 篇使用 `deepseek-v4-pro-0813`；
- 另外 5 篇使用 `gpt-5.6-pro`；
- 两个模型使用同一轮代码、同一版本 Prompt、同一 harness、相同推理强度和可比的运行配置；
- 每轮的随机种子、论文 ID、模型配置、并发和运行状态写入该轮记录；
- 同一轮尽量避免两组样本重叠；若因 Stage05 集合大小或运行失败需要重抽，必须记录原因，不静默替换样本。

两个模型使用相同的角色 Prompt。禁止为某个模型添加专门分支、专用措辞、额外示例或专用恢复指令。模型差异只能在分析阶段记录，不得用来反向污染 Prompt。

### 4.2 每轮必须记录的内容

每轮在 `docs/stage0607_v6/` 中创建一份独立 Markdown 记录，至少包括：

- 本轮目标、代码 commit、Prompt 变更摘要和变更理由；
- 两个模型的实际配置、样本、运行终态和失败分类；
- 每篇论文的 Stage06A、Stage06B、Stage07 和机械状态；
- 对正文/SI 的科学复核结果；
- 代码问题、Prompt/角色问题、模型能力问题和源材料问题的归因；
- 两个模型在同类指标上的对比；
- 是否继续下一轮，以及继续的理由；
- 本轮测试产生的结果目录和可追溯文件。

### 4.3 对比指标

指标用于分析模型行为，不是新的科学硬规则：

1. 完整路线/核心子过程选择是否有正文证据；
2. 输入和参考态闭合判断是否有依据；
3. 软件缺口是否登记且未被单独当作科学拒绝理由；
4. Stage06B 是否保持答案盲和公共面完整；
5. Stage07 审计、修复和最终决定是否一致；
6. 错误批准、错误拒绝、未完成、机械误阻断和静默未发布的数量；
7. Prompt 要求是否被两个模型以相似方式理解。

论文是否最终发布不是单独的成功指标；合理科学拒绝与合理发布同样可以计为正确处理。

## 5. 代码、Prompt 和模型的边界

### 5.1 本轮允许修改

- Stage06A、Stage06B、Stage07 的 Prompt 文本、顺序、术语和最小结构化输出要求；
- 与 Prompt 合同直接相关的通用测试和文档；
- 为保持现有 Prompt 合同可运行而必须进行的最小 transport/schema 兼容修复，但必须单独说明并证明不是论文特例。

### 5.2 本轮默认不修改

- 不增加基于论文、分子、固定数值、软件名称或特定格式的科学 gate；
- 不把电荷、多重度、物质平衡、溶剂、TS 或计算成本的化学裁决写入机械代码；
- 不给 Stage06B hidden answer 或完整 source truth 访问权；
- 不默认新增 Stage07B；只有出现重复、简单、非科学的 transport 阻断，并且确实需要窄 Agent 才另行提出；
- 不改写 Stage00–05 筛选结果；
- 不为了提高通过率强制改变科学拒绝结果。

## 6. 十轮验收与停止条件

本轮最多十轮。每轮完成代码/Prompt 回归和双模型样本审查后，依据以下条件决定是否继续：

- 是否仍存在可重复、模型无关的 Prompt 歧义或职责冲突；
- 是否存在同一 Prompt 要求被两个模型稳定误解的共性模式；
- 是否出现确定性 Stage06/07 代码 bug；若有，先判断是否属于本轮允许的最小通用兼容修复；
- 是否只是单篇源材料不可执行或单次模型遗漏，不得据此添加特例规则。

达到以下状态后可以提前结束，不必凑满十轮：

1. 两个模型都能按角色边界完成任务，科学拒绝和发布状态均可解释；
2. 没有稳定的通用 Prompt 冲突或代码运输 bug；
3. autonomous/reproduction 的公开边界和验收语义一致；
4. 没有公共答案泄漏、Stage06B 越权或科学批准与机械状态混淆；
5. 逐篇复核中，正确处理率达到至少 80%，且该比例不是通过提高拒绝率或添加论文特例获得。

如果十轮结束仍有零散模型遗漏，但没有通用 Prompt 歧义、代码 bug 或角色越权，应将其记录为模型能力限制，不继续追加无穷检查条款。
