# ResearchChemBench 数据管线设计原则与 ARCHE 关系

## 1. 文档目的

本文档说明 ResearchChemBench 数据管线为什么这样设计、四类评估任务如何定义、
论文如何被筛选和转换为完整评估套件，以及本项目与 ARCHE 研究之间的关系。

设计依据包括：

- 飞书文档：[ResearchChemBench 评估任务与数据构造原则](https://sii-czxy.feishu.cn/wiki/FCfMwL2sLiN1Y1ky5gGcd57Hn1f)
- 可选的本地 ARCHE 正文副本：`papers/ARCHE_manuscript.pdf`
- 可选的本地 ARCHE 补充材料副本：`papers/ARCHE_supplementary_information.pdf`

以上 PDF 仅作为本地设计参考，不纳入 Git 版本管理。

## 2. Benchmark 的目标

ResearchChemBench 面向能够调用多个计算化学软件和化学工具的科研智能体。它不只
检查某个工具是否能运行，而是评估智能体能否在受限计算预算内完成以下科研闭环：

1. 理解科学问题和公开输入；
2. 选择并编排适合的计算工具；
3. 生成可核查的中间产物和科学证据；
4. 根据正面或负面结果调整研究路线；
5. 从计算结果中形成有证据支持、边界清楚的结论；
6. 在多体系任务中归纳可解释规律并进行留出预测。

现有基准通常只覆盖单一软件、单一体系、明确指定工具的短任务，或者主要评价代码与
环境复现。ResearchChemBench 希望补充的核心能力是：真实多软件计算化学环境中的
工具编排、竞争假设、判别性计算、负面证据驱动的路线调整、机理抽象和证据溯源。

## 3. 与 ARCHE 的关系

ARCHE 展示了科研智能体在计算化学中的三种代表性能力：

1. 在已报道的邻二胺催化醛醇反应中重建立体控制过渡态和机理；
2. 对未发表的 alpha-碘代硼酸酯 C-I 键断裂问题提出并迭代检验多个机理假设；
3. 从镍催化迁移交叉偶联的多个体系中抽象控制选择性的描述符和预测规律。

ResearchChemBench 不是对 ARCHE 三个案例的逐字复制，而是把这些能力转化为可规模化
构造、可重复运行和可评分的任务合同。二者的对应关系如下：

| ARCHE 能力 | ResearchChemBench 对应任务 | 关键差异 |
| --- | --- | --- |
| 已知研究的机理重建 | 结论引导重建；若公开完整论文路线，则为论文路线复现 | 任务类型由公开给智能体的信息决定，不由论文是否发表决定 |
| 面向未知问题的假设生成、计算验证和路线修正 | 自主科研求解 | Benchmark 固定公开输入、预算、证据要求和评分规则 |
| 跨体系描述符抽象与预测 | 机理规律发现 | 必须设置隐藏体系或隐藏结果，实际检验预测能力 |

ARCHE 的 Case 1 原始设置没有直接公开论文计算路线，因此更接近“具有已知参考发现的
结论引导重建”，不能简单等同于路线复现。Case 2 的核心是原假设被计算结果排除后，
重新定义关键反应组分并修正路线。Case 3 的核心不是描述已有相关性，而是从多体系
结果中形成可解释规律，并在留出体系上验证。

ARCHE 包含知识检索能力，而 ResearchChemBench 的正式评测默认不联网。因此本项目
主要评价 ARCHE 类系统的计算研究闭环，不宣称覆盖其外部文献检索和开放网络知识获取
能力。生成 prompt 中的四类示例保持为通用完整案例，不依赖或提及 ARCHE；ARCHE 只在
设计论证、人工标注和任务质量对照中使用。

## 4. 四类评估任务

每个通过审核的研究只生成一个正式任务。任务类型由分类 LLM 根据该研究最丰富、最
可靠、最适合评分的信息确定，不默认选择最开放或最困难的类型。

### 4.1 论文路线复现

**通俗定义：给出路线，复现结果。**

公开内容包括科学问题、真实输入、论文方法、关键参数和执行路线；隐藏内容包括最终
结果、关键中间产物和论文结论。主要评价：

- 工具调用和跨软件流程执行是否正确；
- 关键参数和输入转换是否完整；
- 计算产物是否有效；
- 关键数值、结构和结论能否在容差内复现。

适合方法、参数和输入最完整，而隐藏路线后任务会因信息不足变得不公平的论文。

### 4.2 结论引导重建

**通俗定义：给出结论，重建证据。**

公开科学问题、真实输入、必要观测和高层结论；隐藏论文路线、关键中间体和具体证据。
主要评价智能体是否能设计判别性验证方案，并用实际计算产物支撑或限定给定结论。

适合高层结论和证据丰富、路线可以隐藏、存在不止一种合理验证方法，但完全开放求解
又过于宽泛的研究。

### 4.3 自主科研求解

**通俗定义：给出问题，自主研究。**

只公开边界清楚的科学问题、真实输入、必要客观观测和计算预算；隐藏研究路线、计算
结果与结论。主要评价：

- 是否提出覆盖主要可能性的竞争假设；
- 是否设计具有信息增益的计算；
- 是否区分科学负面证据与单纯程序失败；
- 是否能根据结果调整路线；
- 结论是否与实际产物一致，并明确不确定性。

适合公开输入足以独立启动、有限预算内可获得判别性证据的研究。机理发现可以作为这类
任务的领域标签，但不是额外的顶层任务类型。

### 4.4 机理规律发现

**通俗定义：给出数据，发现规律。**

公开多个可比较体系的结构、条件和部分结果；隐藏关键描述符、机理解释以及留出体系的
结果。主要评价跨体系抽象、规律稳健性、适用范围、失败边界和留出预测准确性。

适合论文核心贡献是跨体系描述符、结构-性质关系或可预测机理规律，并且有足够体系可
以划分发现集和留出验证集的研究。

## 5. 单论文单任务选择

数据管线先生成来源可追溯的 ScientificRecord，再由分类 LLM 同时比较四类任务，只
选择一个最佳类型，并记录：

```text
selected_task_type
selection_reason
rejected_task_types
```

分类依据至少包括：

- 方法和参数是否完整；
- 起始输入是否真实存在且可物化；
- 论文结论、实验数值和计算产物是否丰富；
- 是否存在竞争假设或有效负面结果；
- 是否包含多个可比较体系和留出预测条件；
- 必需计算是否被当前工具箱覆盖；
- 是否能在预算内运行并建立稳定评分。

若四类任务都不满足输入可用性、工具覆盖、可运行性和可评价性要求，该论文不生成正式
任务。数据产量不能优先于科学可执行性。

## 6. 成本递增的数据管线

管线面对的是大量化学期刊 PDF，因此必须先用低成本方法排除不相关论文，再逐级增加
解析、LLM、计算和人工成本。StudyBundle 只为高潜力论文建立，不是全语料第一步。

### 6.1 PDF 清点与结构化解析

1. 清点文件、计算哈希，将字节级重复路径仅保留在第一阶段审计文件中；
2. 只有去重后的唯一 PDF 才能进入第二阶段和所有后续阶段；
3. 使用 GROBID `processFulltextDocument` 生成 TEI XML；
4. 从 TEI 提取标题、摘要、作者、DOI、发表日期、期刊、卷期页码、关键词和章节结构；
5. 将 TEI XML、结构化 JSON 和展开后的正文文本分别保存；
6. 使用关键词、文本密度和轻量规则判断计算化学相关性；
7. 优先排除纯湿实验、无计算主体和明显无法形成任务的论文。

这一阶段不调用大模型。GROBID 服务采用固定版本和本地模型，避免依赖 PDF 内部元数据
和脆弱的正文正则表达式，并为后续分类提供一致的论文结构。

### 6.2 任务潜力复筛与按需 MinerU

对候选论文检查计算软件、方法、输入数据、补充材料、代码/数据声明、多体系信息和任务
潜力。原生文本质量足够时直接复用；仅对扫描件、复杂排版、公式表格密集或文本提取失败
的候选调用 MinerU。MinerU 不是所有 PDF 的默认入口。

### 6.3 构建 StudyBundle

只为通过前两轮筛选的研究归并以下材料：

- 正文与补充材料；
- 预印本、正式版本和勘误关系；
- 代码仓库、数据仓库、输入文件和原始输出；
- DOI、许可、获取时间和文件校验值。

一个 StudyBundle 表示一项完整研究，而不是一个 PDF 文件。正文、SI 和数据说明不得被
错误计为多个独立样本。

### 6.4 科学证据抽取

抽取模型把研究转换为 ScientificRecord 和 EvidenceUnit。每个科学事实必须尽可能
记录来源文件、页码/段落/图表或仓库路径，并区分论文报告值、实验值、重新计算值和
推断值。LLM 可以协助结构化和提出候选字段，但不能把无来源生成内容直接当作 gold。

### 6.5 单任务分类与完整任务包生成

分类模型选择唯一任务类型。生成模型随后只产生一份公开任务和一份隐藏参考，包括：

- `task_instruction`：智能体看到的任务指令；
- `public_inputs`：可直接运行或验证的公开输入文件和元数据；
- `reference_findings`：用于评分的关键参考发现；
- `evidence_requirements`：每项发现需要的产物和证据；
- `rubric`：结论、证据、执行和科学诚实性的评分规则；
- `provenance`：每个关键字段的来源定位。

每题默认保留 3–10 个 ScoredFinding，而不是用字段数量冒充科学充分性。

### 6.6 自动审计、多角色审核与人工审核

确定性检查负责结构完整性、文件哈希、公开/隐藏隔离、工具映射、数值格式、化学对象和
明显泄漏。多角色 LLM 从科学依据、工具与数据可行性、评价设计、泄漏和难度等角度独立
提出意见。多个角色可以由同一底座模型承担，但必须保存角色、模型名、端点、prompt
版本和输出时间。

模型审核用于发现遗漏和排序人工队列，不能替代真实产物验证和领域专家判断。人工审核
位于高成本漏斗末端，只检查已经通过前序筛选的少量候选。

### 6.7 输入物化与参考运行

正式任务的起始输入至少达到 `materialized + validated`：

| 状态 | 含义 |
| --- | --- |
| described | 论文文字描述过，但没有可运行文件 |
| reconstructible | 可依据明确规则重建 |
| materialized | 已生成或获得实际输入文件 |
| validated | 文件通过格式、化学和一致性检查 |
| reference_executed | 已在目标环境成功完成参考运行 |

默认完成一次真实参考运行，并由独立审核者检查关键产物。随机性强、跨软件转换敏感、
容差难确定或首次运行不稳定的任务，触发第二次运行或第二条验证路线。软件崩溃、输入
错误和不收敛本身不构成负面科学证据。

### 6.8 难度校准与冻结

任务难度依据真实运行时间、资源消耗和智能体试跑结果确定：

- 短任务：不超过 1 小时；
- 中型任务：超过 1 小时且不超过 4 小时；
- 长任务：超过 4 小时，进入独立挑战集。

运行时难度与科研自主性分开记录。发布前使用无工具基线和 3–5 个代表性智能体试跑，
剔除普遍满分、普遍失败、无工具可直接回答或评分分歧过大的题目。最终按 `study_id`
冻结任务、来源清单、参考运行、审核记录和数据划分。

## 7. 证据与答案原则

参考答案应理解为 `ReferenceFinding`，即来源可靠、可由参考产物验证的参考发现，而不是
唯一科学真理。自主任务主要评价智能体是否恢复关键结论、提交有效证据、避免不受支持
的断言并正确表达不确定性。智能体提出论文之外的新结论时，只要不与可靠证据冲突且有
实际产物支持，不应因为没有复述论文而自动扣分。

每个 ScoredFinding 至少包含：

- 参考发现及来源；
- 对应计算产物；
- 数值容差或定性判据；
- 必需证据、可替代证据和明显错误证据；
- 方法依赖、适用范围和不确定性。

完整 Evidence DAG 只用于多阶段机理研究、负面证据触发路线修改、多个主张相互依赖，
或需要留出预测的规律发现任务。基本链路为：

```text
公开输入 -> 可执行步骤 -> 计算产物 -> 验证器 -> 证据 -> 科学主张 -> 适用范围与不确定性
```

## 8. 正式任务的最低准入条件

正式任务至少满足：

1. 论文属于计算化学或计算化学占核心地位；
2. 当前工具箱覆盖绝大部分必要计算能力；
3. 公开输入真实存在、已物化并验证；
4. 方法和计算细节足以在目标环境执行；
5. 至少一次真实参考运行成功；
6. 有 3–10 个来源明确、可判定的参考发现；
7. 公开任务不泄漏标题、DOI、作者和隐藏结论；
8. 替代科学有效路线不会因为不同于论文路线而被无故扣分；
9. 多角色模型审计和独立人工审核完成；
10. 任务在给定预算内可完成，并对不同能力智能体具有区分度。

任务可以标记为 `live_compute`、`hybrid` 或 `offline_analysis`，但必须明确哪些上游结果
作为公开观测，哪些计算必须由智能体完成。只有 PDF 文字描述而没有真实输入文件时，
候选可以继续进入数据资产发现与人工补全队列，但不能直接作为正式实时计算任务发布。

## 9. 与代码的对应关系

- [`config.json`](config.json)：唯一运行配置，控制语料、MinerU、四个 LLM 阶段和工具箱。
- [`assets/toolbox.json`](assets/toolbox.json)：当前可用软件、别名和能力清单。
- [`assets/prompt_examples.json`](assets/prompt_examples.json)：四类任务的可编辑完整示例。
- [`src/ingestion`](src/ingestion)：PDF 清点、解析、去重和 StudyBundle。
- [`src/discovery`](src/discovery)：低成本相关性与任务潜力筛选。
- [`src/curation`](src/curation)：证据抽取、单任务分类、任务包生成和模型审核。
- [`src/delivery`](src/delivery)：正式构建、验证、参考运行和智能体试跑。
- [`src/orchestration/pipeline.py`](src/orchestration/pipeline.py)：从语料到候选任务的流程编排。
- [`papers`](papers)：ARCHE 正文和补充材料的本地设计参考归档。

当前管线输出首先是可审查的候选任务包。只有完成输入物化、参考运行、容差确定和人工
批准后，候选包才升级为 ResearchChemBench 正式评估任务。
