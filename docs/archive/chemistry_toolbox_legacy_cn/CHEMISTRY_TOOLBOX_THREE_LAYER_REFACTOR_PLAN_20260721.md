# 化学工具箱三层执行架构重构计划

日期：2026-07-21

## 1. 目标

保留全部预定义 Scientific/Data Actions，把它们从工具箱的唯一能力边界改为常用、经过验证的第一层。对于未被 Action 预先表达的论文操作，智能体可以直接编写软件原生输入并调用软件，或者编写程序完成计算和分析。三层均由智能体决定是否使用、使用顺序、软件、方法、参数和结果解释。

本次不新增论文专用工作流，不引入自动软件选择，不引入科学参数默认值，不在失败后调用 callback、替换参数或切换 backend。

## 3. 关键设计决策

1. 预定义 Action 不删除、不降级，也不强制优先使用。它适合已经稳定抽象的常见科学操作。
2. 第二层不是 `run_ase` 一类代替智能体决策的流程工具。它只把智能体明确给出的原生文件和 argv 交给一个明确软件。
3. 软件调用方式由版本化的机器可读手册提供。智能体先检查软件，获得本机命令路径、调用格式、输入模式、文件要求、输出行为、本地文档和示例请求，不需要猜测。
4. 第三层不接受隐藏的 inline 表达式或系统生成代码。智能体必须把完整 `.py` 文件写到 workspace，并明确选择一个已有化学运行环境。
5. 长计算使用持久异步作业。MCP 只负责提交和查询，不要求把网络请求超时延长到科学计算总时长。
6. 原生命令由 BackendSpec 与调用手册双重白名单约束，并始终使用 `shell=false`。通用 `mpirun` 不直接暴露为可执行入口。
7. 可编程层的进程和资源限制不是完整的操作系统安全沙箱；运行不可信智能体代码时仍应在容器或调度系统隔离环境中部署 MCP。

## 4. 完成标准

- 101 个既有 Action 的名称、请求契约和执行逻辑保持可用。
- MCP 同时暴露三个层级，且系统提示词不提供固定科研流程。
- 所有带 executable 的 BackendSpec，以及 AiiDA/QCEngine、CENSO、Wannier90、Arkane、AutoMeKin、KinBot、SHARC、Newton-X、TheoDORE、Yambo、VMD 等已安装 runtime-only 软件均有经过检查的调用指南。
- 一个真实原生程序和一个真实 Agent 脚本能完成提交、后台执行、查询和输出收集。
- 输入越界、路径穿越、任意 executable、shell 字符串和隐式 fallback 均不能进入执行器。
- 重要输出能成为带 SHA-256、语义类型、生产者和父产物的 ArtifactRef。
- 完整测试通过后提交 Git，并在修改报告中记录验证命令与已知边界。
