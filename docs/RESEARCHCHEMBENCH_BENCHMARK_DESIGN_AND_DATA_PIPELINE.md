# ResearchChemBench Benchmark 设计与数据管线简介

## 1. 项目定位

ResearchChemBench 是一个面向计算化学科研智能体的评测基准，目标不是测试模型能否回答化学知识题，
也不是测试单个软件命令是否能够运行，而是评估智能体能否围绕真实科学问题完成多阶段计算研究：

- 理解问题并提出可检验的假设；
- 选择合适的软件、方法、参数和计算顺序；
- 编排多个化学工具并正确传递结构、能量、轨迹等中间产物；
- 识别失败、检查收敛性并调整路线；
- 基于新生成且可追溯的计算证据形成可靠结论。

评测时，智能体在隔离工作区中使用统一的 Chemistry MCP 工具箱。所有任务面对相同的工具目录，
由智能体自主选择 Action、Backend、参数和调用顺序；Benchmark 不替智能体选择计算路线，也不在
后台自动切换软件或隐藏失败。

```text
公开任务与输入
      |
      v
外部科研智能体（Codex / Claude Code / OpenCode 等）
      |
      v
统一化学工具箱：发现工具 -> 执行计算 -> 生成 Artifact
      |
      v
研究计划 + 计算轨迹 + 中间证据 + 最终报告
      |
      v
隐藏真值、科学质量门和过程 Rubric 联合评分
```

## 2. 双模式评测设计

每个入选的科学问题原则上构造一对任务：**自主科研模式**和**论文复现模式**。二者共享科学对象、
核心结论和可比的资源预算，但公开信息不同，因此分别考察“自主解决问题”和“忠实执行协议”的能力。

| 设计项 | 自主科研模式 | 论文复现模式 |
|---|---|---|
| 公开内容 | 科学问题、原始输入、实验条件和起始观测 | 输入数据、论文方法、关键参数、计算路线和验证要求 |
| 隐藏内容 | 作者软件路线、方法参数、中间体、路径和最终结论 | 作者完成的答案性结果、关键数值和最终结论 |
| 智能体自由度 | 自主提出假设、选择方法、规划路线、分支搜索和修正 | 在论文协议约束下组织工具，必要时作受控且有说明的兼容替代 |
| 主要能力 | 科学规划、工具选择、证伪、失败恢复和可靠发现 | 协议理解、参数忠实度、跨软件执行、数值验证和结论复现 |
| 成功标准 | 用新计算证据得到受支持的结论，不要求复刻作者动作序列 | 重新生成足够证据，在容差内复现论文结果或结论 |

### 2.1 自主科研模式

自主科研任务只规定问题、输入边界、实验条件和必要的科学有效性要求，不向智能体公开论文采用的
方法与路线。智能体需要自行决定：

1. 应验证哪些假设和替代解释；
2. 使用哪些软件、理论层级和参数；
3. 如何从低成本筛选逐步升级到高精度计算；
4. 何时扩展搜索、何时终止失败路线；
5. 当前证据支持精确结论、定性趋势，还是只能给出范围和不确定性。

这种模式重点区分“能够执行工具”和“能够开展计算科研”。即使最终结论碰巧正确，若没有新的受管
计算证据，或没有验证关键科学假设，也不能获得高分。

### 2.2 论文复现模式

论文复现任务公开从论文及补充材料中重建的计算协议，包括输入结构、软件、方法、参数、工作流、
参考态和验证标准。智能体需要将协议映射到工具箱并完成可审计的重新计算或重新分析。

复现不是简单抄录论文数值。论文的答案性输出和最终结论仍位于隐藏评估侧，智能体必须区分：

- 论文报告的目标值；
- 本轮重新计算得到的结果；
- 因软件版本或资源限制产生的受控偏差；
- 尚未复现或无法确定的部分。

若任务目标是对作者公开的原始输出进行独立再分析，可以把这些原始输出作为输入，但必须要求智能体
生成新的分析 Artifact，并且不能直接提供已整理好的答案。

### 2.3 成对任务的一致性

同一任务对共享以下内容：

- 相同的科学问题和系统身份；
- 相同或可映射的起始结构与实验条件；
- 相同的隐藏科学结论及数值容差；
- 相同的关键科学质量门；
- 可比较的计算资源和时间预算。

两种模式只改变信息披露和过程评分重点。这样可以分析同一智能体在“路线已知”和“路线未知”条件下
的能力差异，也可以判断失败来自执行能力不足，还是科学规划能力不足。

## 3. 计划覆盖的十个任务方向

以下十个方向均采用双模式设计。每篇论文不必覆盖整个方向，但候选任务必须包含至少三个相互依赖的
计算阶段、一个科学验证门和一个可客观评分的结果。

| 序号 | 任务方向 | 自主科研模式示例 | 论文复现模式示例 | 主要评估能力 |
|---:|---|---|---|---|
| 1 | 反应机理、势能面与选择性 | 给定反应物、条件和实验选择性，自主发现竞争路径并解释主产物 | 按论文的构象、DFT、TS、频率、IRC 和自由能路线复现势垒与选择性 | 分支搜索、TS 验证、路径连接、自由能比较 |
| 2 | 构象系综、热化学与性质标定 | 给定分子和观测性质，自主建立构象系综并判断性质来源 | 按 CREST/CENSO、优化、频率和 Boltzmann 加权协议复现构象布居或性质 | 多层级筛选、去重、热化学和系综统计 |
| 3 | 周期表面吸附、反应与成键 | 给定晶体、表面和吸附物，自主搜索位点并解释吸附趋势 | 按论文 slab、覆盖度、周期 DFT、吸附能、PDOS/COHP 路线复现结论 | 周期建模、参考态、结构弛豫和成键分析 |
| 4 | 电子密度、QTAIM 与成键 | 给定结构和成键问题，自主选择密度与拓扑指标验证假设 | 按论文波函数/密度、网格、等值面、QTAIM 或 Bader 参数复现指标 | 密度生成、数值敏感性、临界点和 basin 分析 |
| 5 | 反应动力学、主方程与微观动力学 | 给定物种、条件和观测，自主构建反应网络并预测速率或分支 | 按论文热化学、TST/RRKM、主方程或微观动力学参数复现速率 | 网络构建、速率常数、压力/温度依赖和灵敏度 |
| 6 | 激发态、光谱与光化学 | 给定分子和光谱/动力学观测，自主确定相关电子态与衰变路径 | 按论文 TDDFT/多参考、谱图、耦合或非绝热轨迹协议复现结果 | 态跟踪、光谱指认、耦合、动力学与统计 |
| 7 | 高压结构与多相稳定性 | 给定候选结构和压力范围，自主确定稳定相序与相变区间 | 按论文结构搜索、压力网格、EOS、焓和声子路线复现相图 | 结构搜索、压力计算、焓交叉和稳定性验证 |
| 8 | 声子、非谐性与热输运 | 给定晶体和温区，自主判断动力学稳定性并设计热输运计算 | 按论文超胞、位移、力常数、声子和热导率参数复现曲线 | 批量力计算、力常数组装、收敛和虚频判定 |
| 9 | 分子动力学、增强采样与自由能 | 给定体系和观测，自主选择力场、CV、采样方法并估计自由能 | 按论文拓扑、平衡、窗口、偏置和 MBAR/PMF 协议复现结果 | 系统构建、采样规划、轨迹分析和收敛诊断 |
| 10 | 描述符发现与催化剂设计 | 给定结构—性质数据，自主生成特征、发现描述符并验证泛化 | 按论文数据划分、电子结构特征和 SISSO/回归流程复现模型 | 数据防泄漏、特征选择、稳健性和外部验证 |

首批任务优先选择反应机理、构象系综、周期表面和电子密度方向；随后扩展到动力学、激发态和
高压相稳定性，最后加入资源需求更高的声子、分子动力学与描述符发现任务。

## 4. 任务数据组织

每个正式任务由公开任务包和评估侧隐藏信息组成：

```text
tasks/<task_id>/
├── task_info.json                 # 任务描述、模式、要求和交付物
├── data/benchmark_data/           # 智能体可见的输入结构、条件和协议
│   ├── input_manifest.json        # 文件大小、哈希和角色
│   └── ...
└── target_study/
    └── ground_truth.json          # 仅评估器可见的结论、Rubric 和质量门
```

公开输入根据模式控制披露程度，但不得包含整理好的答案、作者最终数值、已完成的答案性计算链，或能
直接反推出隐藏结论的文件名和说明。隐藏部分保存：

- 参考结论和允许的数值/结构容差；
- 每条结论需要的最低证据；
- 过程评分 Rubric；
- 关键失败条件和证据门；
- 工具箱可行性与 Gold Run 基线；
- 公开输入 manifest 的哈希。

所有模式统一要求四类交付物：初始及修订后的研究计划、结论到 Artifact 的证据映射、失败或未决
路线日志，以及区分“新计算、论文结果、实验观测和推断”的最终研究报告。

## 5. 评估与评分

ResearchChemBench 采用双轴 100 分评分：

```text
最终分数 = 科学结论分 C × 科研过程分 P / 100
```

### 5.1 科学结论轴

隐藏真值被拆成若干独立科学结论，每条结论定义权重、接受规则和必要证据。结论必须由本轮新生成的
有效 Artifact 支持；猜测正确、复制论文结果或只有文字论断均不计为有效结论证据。

### 5.2 科研过程轴

两种模式使用相同的 20/15/15/20/10/10/10 权重结构，但评价重点不同：

| 过程维度 | 分值 | 自主科研重点 | 论文复现重点 |
|---|---:|---|---|
| 路线设计 / 协议理解 | 20 | 假设、备选路线、判据和停止条件 | 正确理解论文路线及依赖关系 |
| 方法、参数与工具 | 15 | 自主选择是否科学合理 | 与论文协议和参考态是否一致 |
| 受管计算与 Artifact 传递 | 15 | 是否真实执行并正确串联计算 | 是否重新计算而非抄录结果 |
| 验证与不确定性 | 20 | 证伪、敏感性和替代解释 | 数值质量、收敛和论文比较容差 |
| 失败诊断与恢复 | 10 | 是否据失败主动调整路线 | 是否受控恢复并记录协议偏离 |
| 资源效率 | 10 | 搜索宽度、层级和停止是否合理 | 在保持协议有效时高效执行 |
| 溯源与可复现报告 | 10 | 结论是否链接到新证据 | 论文目标与重算结果是否清楚分离 |

乘法评分避免“过程很好但结论错误”或“猜中答案但没有科研过程”获得高分。此外还设置：

- **Evidence gates**：缺少关键状态、TS/声子/收敛验证或统一参考态时限制最高分；
- **Critical failures**：伪造证据、泄漏隐藏答案、把论文值冒充本轮计算等情况直接判零；
- **Objective not-scorable**：若有证据证明输入、框架或基础设施本身故障，则记为客观不可评分，而不把故障算作智能体能力。

## 6. 七阶段数据管线

数据管线从大规模期刊 PDF 语料中筛选适合的论文，收集可复现资产，构造候选任务并进行独立审计。

```text
PDF 语料
  -> 01 清点去重
  -> 02 结构化解析
  -> 03 软件覆盖门控
  -> 04 资源可行性门控
  -> 05 研究资产收集与解析
  -> 06 双模式候选任务构建
  -> 07 独立任务审计
```

| 阶段 | 主要工作 | 关键产物 / 决策 |
|---|---|---|
| Stage 01 论文清点与去重 | 计算文件哈希，结合 DOI、标题和文件角色识别正文、补充材料和重复文件 | 唯一主论文清单及正文—补充材料关系 |
| Stage 02 结构化解析 | 用 GROBID 提取标题、摘要、章节、方法、参考文献和 TEI；单篇失败时可降级到 `pdftotext` | 统一论文结构、正文和元数据 |
| Stage 03 软件覆盖门控 | 用 Softcite 提取实际核心软件，与工具箱软件别名和能力表匹配 | 只让核心软件可直接执行的论文进入主流程 |
| Stage 04 资源可行性门控 | 提取 CPU、GPU、内存、时间和体系规模，并与可配置上限比较 | 排除明确超预算且不能合理缩小的论文 |
| Stage 05 资产收集与解析 | 从 DOI、Availability、出版社、Crossref、DataCite、OpenAlex、GitHub、Zenodo、OSF 等最多三轮发现资产 | 原始文件、哈希、来源、版本、解析结果和未解决线索 |
| Stage 06 Builder 任务构建 | 根据论文、资产和工具箱整理科学记录，分别构造自主科研与论文复现候选；证据不足时允许 abstain | 公开任务、公开输入、隐藏参考、评分 Rubric 和证据映射 |
| Stage 07 Judge 独立审计 | 在独立会话中检查论文忠实性、数据充分性、工具箱支持、答案泄漏、评分质量和资源可行性 | `pass`、`revise` 或 `reject` |

当前 Builder 的一次调用输出一个候选任务。生成双模式数据时，对同一经过冻结的论文证据分别执行
自主科研和论文复现两个受约束的构建过程，再进行独立审计；Judge 不读取 Builder 的会话或草稿。

### 6.1 Stage 01-04：低成本筛选

前四阶段用于尽早淘汰不适合的论文。候选至少满足：

- 核心软件可由工具箱直接执行，或存在经过批准的方法等价路线；
- 计算部分至少包含三个相互依赖阶段或两个 Action family；
- 有收敛性、结构、能量、速率、谱峰、相变压力等客观目标；
- 有足够输入和中间证据构造独立任务；
- 代表性子任务能够在固定资源预算内完成；
- 不依赖未公开数据或不可替代且不受支持的软件。

数据选择优先采用仅凭论文正文和补充材料即可闭合计算链的工作。若论文明确引用公开代码库或数据仓库，
则必须由 Stage 05 获取并冻结具体版本、哈希和来源后才能使用，不能依赖评测时临时变化的外部文件。

单点能、单次几何优化、单张 DOS/能带、单次 docking、纯可视化或固定脚本式高通量任务通常缺乏
工具编排和科研决策价值，不作为优先评测样本。

### 6.2 Stage 05：有边界的资产闭环

Stage 05 不假设论文正文已经包含全部文件。它在固定轮次、文件数、容量和网络预算内寻找补充材料、
代码、结构、输入输出、轨迹和配置，并对每个资产保存：

- 来源 URL、发现证据、版本和许可证信息；
- SHA-256、文件类型、父子关系和下载状态；
- 原始字节、结构化 JSON 与可读 Markdown/TXT；
- 解析器、解析状态、失败原因及未解决线索。

原始资产不可被解析文本替代，下载内容默认不执行。`asset_manifest.jsonl` 是 Builder 使用的唯一可信
资产索引，从而保证每个公开输入和隐藏结论都可追溯到具体论文证据。

### 6.3 Stage 06-07：构建与审计分离

Builder 只能使用已经收集的论文证据和工具箱中真实存在的能力，不能发明方法、参数、结果或文件。
程序还会确定性检查公开资产 ID、软件覆盖、Action 名称、Rubric 总分和明显答案泄漏。

Judge 使用新的隔离工作区和会话，独立检查：

1. 任务是否忠实于论文；
2. 公开输入是否足以完成任务；
3. 当前工具箱和资源是否真正支持；
4. 自主模式是否隐藏路线，复现模式是否隐藏答案；
5. 评分规则是否客观、可执行且覆盖关键科学结论；
6. 是否需要 `pass`、`revise` 或 `reject`。

当前数据管线在 Judge 输出后结束，不自动修改任务，也不把人工发布流程混入自动构建阶段。

## 7. 数据集质量控制

正式进入评测集前，每个任务对还应通过以下检查：

- **去污染**：自主任务不出现论文方法和目标数值；复现任务不出现作者最终答案；
- **输入完整性**：结构、身份、单位、电荷、自旋、参考态和文件哈希一致；
- **可执行性**：所需软件、模型、势函数和参数文件在目标环境中可用；
- **Gold Run**：由专家或受控参考流程执行代表性任务，校准时间、容差和预期证据；
- **双轨一致性**：两种模式共享科学结论，但信息披露和过程 Rubric 严格区分；
- **评分可靠性**：确定性规则负责公式、分数上限、证据门和提交有效性，LLM Judge 只负责证据解释；
- **版本化**：论文、资产、工具箱、任务定义和隐藏真值均保存版本与哈希。

## 8. Benchmark 期望回答的问题

通过十个方向和双模式任务，ResearchChemBench 希望系统回答：

1. 智能体能否把自然语言科学问题转化为可执行的多阶段计算计划？
2. 在论文协议已知时，智能体能否忠实、稳定地复现计算结果？
3. 在路线隐藏时，智能体能否自主选择方法、修正失败并得到可靠发现？
4. 智能体能否正确组合不同软件，而不是只会调用单个工具？
5. 最终结论是否由真实、可追溯并经过验证的计算证据支持？
6. 能力差异来自工具执行、科学规划、验证意识、资源管理，还是报告与溯源？

因此，ResearchChemBench 的核心评测对象不是最终一句答案，而是智能体从问题定义、工具编排、
计算执行、质量控制到科学结论的完整科研闭环。

## 9. 基于远端语料与当前工具箱的建议主评测方向

本节是对第 3 节原始十个方向的增量修订建议，不覆盖或删除原始设计。建议来自对
`en-paper-hzzj` 远端语料中 21,836 个 PDF、其中 21,121 条可匹配元数据，以及一次 500 篇随机
样本 Stage 00-03 实跑结果的联合分析。题名主题允许重叠：有机合成、反应与催化约占 36.84%，
材料、界面和多孔体系约占 20.28%，光化学与光谱约占 17.60%，生物、酶和药物约占 16.96%，
能源存储与电化学约占 13.70%；高压与相稳定性、声子与热输运的题名命中率分别只有约 0.31%
和 0.15%。

结合当前工具箱已经验证的分子量子化学、周期电子结构、反应动力学、分子动力学、自由能、
激发态、构象搜索、密度分析、机器学习和生物分子计算能力，首批正式评测建议采用以下十个
主方向：

| 序号 | 建议主评测方向 | 典型计算链 | 采用理由 |
|---:|---|---|---|
| 1 | 反应机理、过渡态与选择性 | 构象搜索 -> 反应路径/TS -> 频率/IRC -> 自由能与选择性 | 远端语料最丰富，Gaussian、ORCA、xTB、CREST、GoodVibes 等工具链完整 |
| 2 | 构象系综、热化学与溶液性质 | 构象生成 -> 多层级筛选 -> 热校正 -> Boltzmann 系综/性质 | 能评估跨工具编排、去重和统计，不局限于单点计算 |
| 3 | 周期表面、吸附与异相催化 | slab/位点构建 -> 周期弛豫 -> 吸附/势垒 -> 电荷与成键分析 | 催化语料充足，VASP、Quantum ESPRESSO、CP2K、LOBSTER 等已经覆盖 |
| 4 | 能源材料、缺陷、界面与离子输运 | 晶体/缺陷构建 -> 周期 DFT/NEB/MD -> DOS、电荷、迁移势垒或输运 | 电池、固态电解质、钙钛矿和电催化论文在远端语料中明显多于高压论文 |
| 5 | 分子电子结构、成键和基态性质/光谱 | 波函数或密度生成 -> 电荷/轨道/拓扑分析 -> NMR、IR、Raman 等性质 | 将原 QTAIM 窄方向扩展到更常见且工具箱可执行的基态电子结构任务 |
| 6 | 激发态、光化学与非绝热过程 | 激发态计算 -> 光谱/态指认 -> 耦合或势能面 -> 动力学/统计 | 光催化、发光和光谱语料充足，ORCA、OpenMolcas、BAGEL、SHARC 等可组合 |
| 7 | 反应动力学、主方程与微观动力学 | 热化学 -> 速率常数 -> 网络/主方程 -> 灵敏度与条件扫描 | 论文数量较少但科研闭环清晰，Cantera、CatMAP、MESS、MESMER、RMG 等能力突出 |
| 8 | 分子动力学、增强采样、溶剂化与自由能 | 体系构建 -> 平衡/采样 -> PMF/自由能 -> 收敛与误差分析 | GROMACS、AMBER、CHARMM、OpenMM、PLUMED、PyMBAR 等形成完整执行链 |
| 9 | 生物分子模拟、对接与结合自由能 | 结构/质子化/拓扑 -> docking/MD -> 结合能或构象分析 -> 验证 | 生物、酶和药物论文占比较高，可使用 Vina、GNINA、GROMACS、AMBER、OpenMM 等 |
| 10 | 计算筛选、描述符、机器学习势与材料设计 | 数据整理 -> 特征/模型 -> 验证 -> 候选筛选或下游计算 | 扩展原描述符方向，覆盖 SISSO、gplearn、DeepMD、MACE、NequIP、CHGNet 等能力 |

原第 7 个“高压结构与多相稳定性”和第 8 个“声子、非谐性与热输运”方向仍有科学价值，且
工具箱具备 AIRSS、VASP、Phonopy、Phono3py、TDEP 和 ShengBTE 等能力，但当前通用远端语料
中完整候选极少、资源需求较高。它们暂作为需要定向采集的扩展挑战集，不作为首批随机语料
筛选的主配额方向。

## 10. Stage 00-03 高精度筛选目标与门控建议

> 当前实现决策（2026-08-10）：Stage 02 已回退到原有 map-reduce 判断，并采用纯计算化学硬门控。
> 只有 `computational_content_confirmed` 可以进入 Stage 03；当前作者实施过物理实验的混合论文均
> 不通过。下述“计算主导混合论文”方案保留为历史设计讨论，不代表当前运行策略。

Stage 00-03 的目标是产生高精度候选池，不是尽可能保留所有包含计算片段的论文。建议把最终
累计保留率控制在约 5%-10% 作为运行质量监测指标，但不得通过随机丢弃、固定 Top-K 或硬配额
实现。实际保留率应由可解释的科学判据决定；高质量语料批次可以略高，低质量批次可以低于 5%。

### 10.1 Stage 02：严格确认计算主导性

纯计算论文可以直接进入 Stage 03。混合计算-实验论文只有同时满足以下条件才允许进入：

1. 论文的中心科学问题至少有一个必须依赖作者实际完成的分子或材料计算才能回答；
2. 计算形成不少于三个相互依赖的科学步骤，或至少两个相互依赖的计算方法/软件阶段；
3. 正文或 SI 中存在完整的方法协议、输入体系、关键参数和作者生成的计算结果；
4. 至少一个摘要、结果或结论层面的核心 claim 由计算直接产生，而不是计算事后解释实验；
5. 删除计算部分后，论文至少一个主结论将无法成立。若实验结果和主要创新仍基本完整，则计算
   应判为 supporting 并淘汰；
6. 计算证据必须跨越“方法”和“结果/结论”两个语义位置，单个 DFT 图、单次 docking、常规拟合、
   仅在 SI 出现的辅助计算或只用于佐证实验趋势的计算均不能通过。

Stage 02 应把证据抽取和中心性裁决拆开。第一轮只抽取可验证证据，并为每条证据记录正文/SI、
章节类型、计算步骤、生成结果和支持的 claim；第二轮由独立裁决调用执行“反事实中心性测试”，
同时比较计算贡献与作者实验贡献。对混合论文，只有两轮均为高置信度且确定性校验通过时才设置
`passed=true`。建议新增或持久化以下字段：

- `central_scientific_question`、`central_claim_ids` 和每个 claim 的计算证据映射；
- `computational_workflow_steps` 及步骤依赖关系；
- `method_section_evidence_ids`、`result_section_evidence_ids`、`conclusion_evidence_ids`；
- `counterfactual_without_computation`：`main_claim_fails`、`main_claim_survives` 或 `uncertain`；
- `computation_primary_reason` 和 `experiment_primary_reason`，禁止只输出笼统的“计算很重要”。

任何证据不足、中心性有争议或只有 supporting 计算的论文都不进入 Stage 03，但其完整判定记录仍
保留在统一 registry 中，以便以后构建其他类型的数据集。

### 10.2 Stage 03：只放行已确认的软件闭环

Stage 03 不应再把所有高召回候选都计为通过。默认严格模式下：

- `software_covered` 才直接通过；
- `software_coverage_probable` 只有在软件清单完整、所有必要实体均映射到冻结工具箱目录、没有必要
  软件或自定义实现未解决时才可升级为通过；
- `mixed_workflow_candidate` 和 `software_inventory_unconfirmed` 不进入后续主流程；
- 至少存在一个具有科学意义的完整计算 workflow，且其中所有 core compute、required preprocessing
  和 required analysis 软件都在工具箱中；
- 可视化、仪器控制和实验晶体学软件不能错误阻断独立计算 workflow，但明确需要的 NBO、AIMAll、
  COMSOL、Materials Studio、CASTEP 等未安装程序也不能用“可由 Python 替代”自动视为覆盖；
- 软件别名命中必须同时具有可验证的程序使用语境，不能仅凭短缩写匹配，以避免把化学物种缩写
  错映射为软件；
- `cost_unconfirmed` 不再默认通过。需根据体系规模、方法级别、计算步骤、采样长度和任务数量形成
  保守成本区间；仍无法判断时进入 hold，而不是计入通过率。

### 10.3 预期漏斗与校准方式

以当前 500 篇随机样本为参考，建议将漏斗目标设为：Stage 01 保留约 85%-95%，Stage 02 严格门控
后累计保留约 10%-20%，Stage 03 软件与成本闭环后累计保留约 5%-10%，必要时可以更低。该范围
是诊断指标而非代码中的通过率条件。

每次修改 Stage 02 或 Stage 03 后，应在固定人工审查集上报告纯计算、计算主导、实验主导、软件
完整覆盖和软件不完整五类的 precision、recall 与混淆矩阵，再在未参与调参的随机 holdout 上复核。
只有高精度目标得到改善时才接受修改，不能因为恰好达到 5%-10% 的数量目标而接受规则。
